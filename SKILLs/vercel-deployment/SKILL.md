# Vercel部署指南

## 1. 简介

### 1.1 Vercel平台概述
Vercel是一个现代化的静态网站和Serverless Functions部署平台，专注于前端和无服务器后端的部署。它提供了快速的部署速度、全球CDN分发、自动HTTPS、预览环境等特性，是前端项目部署的首选平台之一。

### 1.2 为什么选择Vercel
- **简单易用**：部署流程简化，支持一键部署
- **性能优异**：全球CDN分发，快速响应
- **Serverless集成**：内置Serverless Functions支持
- **开发体验**：预览环境、分支部署等特性
- **生态完整**：与Next.js、React等框架深度集成

### 1.3 适用场景
- 静态网站和单页应用
- 前端框架项目（React、Vue、Vite等）
- Serverless后端API
- 前后端一体化项目

## 2. 部署准备

### 2.1 项目结构要求
- **前端项目**：需要有构建配置文件（如package.json）
- **后端API**：需要在`api`目录下创建Serverless Functions
- **配置文件**：可选的`vercel.json`配置文件

### 2.2 依赖配置
- 确保`package.json`中包含正确的依赖和脚本
- 前端项目需要包含构建脚本（如`npm run build`）
- 后端API需要包含必要的依赖

### 2.3 环境变量设置
- 在Vercel项目设置中配置环境变量
- 前端项目中使用`import.meta.env.VITE_`前缀的变量
- 后端Serverless Functions中使用`process.env.`访问变量

## 3. 前端部署

### 3.1 静态网站部署
- 直接将静态文件部署到Vercel
- 支持HTML、CSS、JavaScript等静态资源
- 自动处理路由和404页面

### 3.2 Vite项目部署
- 确保`package.json`中包含构建脚本
- 构建输出目录默认为`dist`
- Vercel会自动检测Vite项目并使用正确的构建配置

### 3.3 路由配置（vercel.json）
- 用于自定义路由规则
- 支持重写、重定向、标头等配置
- 示例配置：
  ```json
  {
    "version": 2,
    "routes": [
      { "src": "/api/(.*)", "dest": "/api/$1" },
      { "src": "/(.*)", "dest": "/index.html" }
    ]
  }
  ```

### 3.4 环境变量使用
- 前端项目中使用`import.meta.env.VITE_VARIABLE`
- 确保在Vite配置中正确处理环境变量
- 开发环境和生产环境的环境变量管理

## 4. 后端部署

### 4.1 Serverless Functions创建
- 在`api`目录下创建函数文件
- 支持JavaScript和TypeScript
- 每个文件对应一个API端点

### 4.2 API端点结构
- **单个端点**：`api/endpoint.js`
- **嵌套端点**：`api/resource/[id].js`
- **批量端点**：`api/resource/batch.js`

### 4.3 数据库集成
- 支持Supabase、MongoDB、PostgreSQL等数据库
- 在Serverless Functions中使用数据库客户端
- 环境变量存储数据库连接信息

### 4.4 中间件处理
- 可以在API函数中实现中间件逻辑
- 支持CORS、认证、日志等功能
- 使用异步/await处理请求和响应

## 5. 多环境部署

### 5.1 环境变量管理
- 为不同环境设置不同的环境变量
- 使用Vercel的环境变量管理界面
- 支持开发、预览、生产环境的变量配置

### 5.2 分支部署
- 每个Git分支自动创建预览部署
- 可以为特定分支设置不同的环境变量
- 支持分支保护和部署规则

### 5.3 预览环境
- 每次提交都会生成预览URL
- 预览环境与生产环境隔离
- 便于团队协作和测试

## 6. 常见问题及解决方案

### 6.1 部署错误排查
- 查看Vercel控制台的构建日志
- 检查依赖安装和构建过程
- 确认环境变量配置正确

### 6.2 API 404错误
- **原因**：API端点文件结构不正确
- **解决方案**：
  - 确保API文件在`api`目录下
  - 检查文件路径和文件名
  - 验证`vercel.json`路由配置

### 6.3 环境变量不生效
- **原因**：环境变量前缀不正确或未配置
- **解决方案**：
  - 前端使用`VITE_`前缀
  - 后端使用`process.env.`访问
  - 确保在Vercel控制台中正确配置

### 6.4 构建失败
- **原因**：依赖问题、构建脚本错误
- **解决方案**：
  - 检查`package.json`配置
  - 确保所有依赖正确安装
  - 验证构建命令是否正确

## 8. 项目案例

### 8.1 本次项目的部署经验
- **项目结构**：前后端一体化，前端使用Vite，后端使用Serverless Functions
- **部署步骤**：
  1. 配置`vercel.json`路由规则
  2. 创建Serverless Functions处理API请求
  3. 集成Supabase数据库
  4. 设置环境变量
  5. 部署到Vercel

### 8.2 具体问题及解决方案

#### 8.2.1 API 404错误
- **问题**：批量提交API端点返回404
- **原因**：API文件结构不正确
- **解决方案**：
  - 创建`api/annotation/batch.js`文件
  - 确保文件导出正确的处理函数
  - 验证路由配置

#### 8.2.2 环境变量不生效
- **问题**：前端无法读取环境变量
- **原因**：环境变量前缀不正确
- **解决方案**：
  - 使用`VITE_`前缀
  - 在代码中使用`import.meta.env.VITE_VARIABLE`
  - 确保在Vercel控制台中正确配置

#### 8.2.3 构建失败
- **问题**：构建命令执行失败
- **原因**：构建脚本配置错误
- **解决方案**：
  - 修改`package.json`中的构建脚本
  - 使用`node --experimental-modules`处理ES模块
  - 确保依赖正确安装
